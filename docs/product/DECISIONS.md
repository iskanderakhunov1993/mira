# Журнал продуктовых решений

## Формат

Для каждого решения фиксировать дату, контекст, решение, причину, ожидаемый эффект и условие пересмотра.

## 2026-07 — Local-first без обязательного аккаунта

- **Решение:** хранить данные локально, не требовать регистрацию.
- **Причина:** приватность, простота MVP, контроль пользователя.
- **Пересмотр:** при появлении подтверждённой потребности в синхронизации.

## 2026-07 — Основные функции бесплатные

- **Решение:** не закрывать цикл, дневник, историю и экспорт paywall.
- **Причина:** доверие и базовая полезность продукта.

## 2026-07 — Hormonoscope только по личным данным

- **Решение:** отказаться от утверждений по фазам и гормонам; использовать похожие дни прошлых циклов.
- **Причина:** снизить псевдонаучность и повысить объяснимость.
- **Порог:** минимум три похожих дня с отметками.

## 2026-07 — Циклоскоп как отдельная игровая функция

- **Решение:** отделить атмосферный прогноз от аналитики здоровья.
- **Причина:** сохранить лёгкость и эмоциональную ценность без смешения с медицинским слоем.
- **Ограничение:** не использовать фазу, гормоны, симптомы и health-метрики.

## 2026-07 — Настраиваемая главная

- **Решение:** Hormonoscope, Циклоскоп и вторичные карточки можно скрыть.
- **Причина:** снизить перегрузку и поддержать разные цели пользователей.

## 2026-07-18 — P0: единый безопасный прогнозный контракт

- **Решение:** показывать на Today и в календаре только диапазон возможного начала месячных; не показывать календарное фертильное окно и карту физиологических фаз в основном сценарии.
- **Причина:** календарный расчёт не подтверждает овуляцию и не должен создавать контрацептивную или медицинскую уверенность.
- **Реализация:** UI использует `forecast.start–forecast.end`; ожидаемая длительность кровотечения не выдаётся за диапазон начала.

## 2026-07-18 — P0: Hormonoscope только как личное наблюдение

- **Решение:** удалить фазово-гормональную версию из активного кода и не показывать демонстрационный персональный прогноз при недостатке данных.
- **Причина:** сохранить один объяснимый контракт — только заполненные похожие дни личной истории, минимум три дня из предыдущих циклов.
- **Обратная связь:** оценивать полезность наблюдения, а не «совпадение прогноза».

## 2026-07-18 — P0: проверяемый контроль локальных данных

- **Решение:** согласовывать IndexedDB и localStorage по монотонной revision; подтверждать удаление повторным чтением; исключать профиль, медицинский check-in, интимные поля и заметки из обычной копии.
- **Причина:** ложное подтверждение удаления, восстановление устаревшей копии и неожиданный sensitive export несовместимы с local-first обещанием.

## 2026-07-18 — P1: offline app shell без кеширования health API

- **Решение:** production-сборка регистрирует собственный service worker, кеширует только same-origin app shell и статические ресурсы и использует сохранённый `/` как fallback для offline navigation.
- **Причина:** local-first продукт должен повторно открываться без сети, но не должен создавать новый сетевой или health-data cache.
- **Ограничение:** первый запуск требует сети; feedback и внешние материалы не обещаются offline; обновление shell требует повышения cache version.

## 2026-07-18 — P1: browser regression gate для критического пути

- **Решение:** проверять в mobile Chromium путь onboarding → первая запись → reload persistence → Calendar, а также safe export → подтверждённое удаление → reload.
- **Причина:** локальное хранение и контроль данных должны подтверждаться через реальный браузерный сценарий, а не только unit-тестами функций.
- **Accessibility baseline:** критические экраны и диалоги не должны содержать активные кнопки или модальные окна без доступного имени.
- **Ограничение:** это baseline критического пути, а не полный WCAG-аудит всех экранов и состояний.

## 2026-07-19 — Today как спокойный центр ежедневной ориентации

- **Решение:** верх Today строится вокруг календарной ленты, одного крупного прогноза и трёх быстрых действий: месячные, симптомы и дневник.
- **Причина:** пользователь должен за несколько секунд понять ближайший ориентир и сразу перейти к записи, без карточного дашборда в первом экране.
- **Ограничение:** визуальная композиция может опираться на знакомый паттерн cycle-tracker, но Mira не показывает «вероятность забеременеть» и сохраняет диапазон вместо точной даты.

## 2026-07-24 — Server-first хранение вместо локальной health-базы

- **Решение:** заменить активное IndexedDB/localStorage-хранилище на Mira API и PostgreSQL; сохранять пользовательский `AuraState` в зашифрованном виде и защищать обновления монотонной `revision`.
- **Авторизация:** Telegram Mini App передаёт `initData` backend-серверу для проверки подписи; API выдаёт короткоживущую сессию внутреннему `user_id`.
- **Причина:** дать одному пользователю общую историю в Telegram и PWA и не оставлять health-данные в постоянном хранилище браузера.
- **Приватность:** ключ шифрования хранится отдельно от БД; health-данные не попадают в логи, service worker, localStorage или IndexedDB; экспорт и удаление остаются доступны.
- **Ограничение:** история требует сети; browser-PWA login через Telegram OIDC является следующим обязательным шагом перед публичным запуском.
- **Отменяет:** решение «Local-first без обязательного аккаунта» и локальный storage-контракт от 18 июля 2026 года для активной версии продукта. Старые записи сохраняются только как исторический контекст.
